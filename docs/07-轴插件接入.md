## 如何注册

这是受信任的进程内扩展入口，尚无 DLL 扫描或 CLI 安装命令。实现 IAxisPlugin，在 src/Lilara.Core/Program.cs 创建 CoreHost 后、创建会话或启动控制面前注册：

    var host = new CoreHost(dataRoot, workingDirectory);
    host.Plugins.Register(new StylePlugin());
    host.Plugins.Seal();

最小插件如下，加入应用源码后注册即可使用：

    using Lilara.Core.Plugins;

    public sealed class StylePlugin : IAxisPlugin
    {
        public PluginIdentity Identity => new("style", "1");
        public IReadOnlyList<AxisDefinition> Axes =>
        [
            new() { Id = "style.detail", Label = "详细程度",
                Values = ["brief", "detailed"], DefaultValue = "brief",
                LevelDescriptions = new Dictionary<string, string>
                {
                    ["brief"] = "回答简洁，优先给出结论与必要信息。",
                    ["detailed"] = "详细解释理由、步骤与具体示例。"
                } }
        ];
        public IReadOnlyList<AxisCapability> Capabilities => [AxisCapability.None];
        public IReadOnlyList<PromptContribution> Prompt(AxisSnapshot snapshot) => [];
    }

注册后新建会话，在头的轴下拉选择档位，或通过已有 session.setAxis 命令设置 axis="style.detail"、value="detailed"。注册表首次绑定或运行期查询时封闭，后续注册会被拒绝。

## 当前等级解释与浮动上下文

核心的主动性、权限、安全和验证强度均有逐等级解释，和合法值共同声明在 Kernel/Axes.cs。模型请求只携带当前选中等级的解释，位于浮动槽的轴表之后；不会同时塞入其他等级的说明。effort、temperature 继续只作为请求参数，不进入提示词。主动性解释描述模型应如何行动，不新增调度或强制续跑机制；权限说明对应现有 Gate，安全与验证强度仍是提示。

插件可选填 LevelDescriptions，键为 Values 中的等级，值为该等级的解释。宿主规范化键、拒绝未知等级、大小写重复键、空白解释和超出单字段限制的内容，并在注册时复制为只读字典。可只描述部分等级；未配置解释的等级保持原有行为，不凭空生成说明。InContext=false 的轴即使配置了解释也不注入。

宿主从同一步轴快照自动生成 Floating 字段，例如 [style/axis-level.detail]，正文为“详细程度 (style.detail) detailed：详细解释理由、步骤与具体示例。”插件无需在 Prompt 回调重复拼接。axis-level. 是宿主保留的字段键前缀，回调不得使用；自动字段与回调字段共享数量、单字段字节和总字节限制。等级解释属于运行期定义，不写入会话历史或持久化轴值，磁盘格式仍为 7。

系统提示词包含固定机制说明：浮动上下文由 Lilara 框架提供，以步开始快照生成，同一步内一致、下一步可变；它不是用户新指令、模型发言或工具结果，也不自行授予权限。默认模板与非空自定义系统预设都携带这段说明；自定义原文保留在前。显式空预设且没有插件系统贡献时仍不生成系统块；若插件贡献系统内容，该系统块同样附有说明。无论系统块是否存在，非空浮动块都自行声明框架来源，包括只有插件字段的情况。

切换等级只更新浮动块，不把当前等级解释移入系统或首要槽；本次新增固定机制说明会使升级后的系统前缀变化一次。

## 契约与边界

- 轴命名为 plugin-id.axis-id；插件不能占用核心轴或其他插件命名空间。注册原子校验，定义、允许值与 capability 列表均复制为只读集合。枚举值不区分大小写匹配，保存声明中的规范拼写。
- 每个新会话保存插件身份、精确版本和创建时默认值。已保存值优先；缺失键从会话绑定的默认值恢复。旧会话不自动启用后来安装的插件。尚无给旧会话追加绑定或迁移版本的命令。
- 插件缺失、版本不一致或轴 schema 不兼容时保留原数据，控制面仍可打开，拒绝该插件改轴及模型推进；不静默跳过贡献。重新注册匹配版本后可继续。版本采用精确匹配，不推测语义版本兼容范围。
- 状态与会话格式版本升为 7。旧文件仍可读，读取不回写；下次写入使用当前版本，防止旧核心静默覆盖插件字段。无插件时字段为 null 并省略，不额外输出空对象。金样仅更新格式版本，插件字段由集成测试验证。
- 同一步的模型参数、核心尾块和插件贡献使用同一轴快照。工具权限仍在执行相位读取核心权限轴，保留原有即时生效规则。失败回滚保留控制面期间修改的核心轴和插件轴。
- InContext=false 的插件轴仅供保存和控制面显示，不提供给提示词回调。回调可见本插件可见轴和核心可见轴，不含其他插件轴、effort 或 temperature。该投影不是对恶意插件的隔离：插件是进程内受信任代码。
- 字段身份为 (slot, pluginId, key)，重复即拒绝，按 pluginId/key 的 ordinal 顺序合并。渲染保留 [pluginId/key] 标识及正文，不允许跨插件伪造归属；正文仍是自然语言，未提供通用模板语言或内容沙箱。
- 每插件最多 64 个字段，单字段正文最多 16 KiB UTF-8，总贡献上限 64 KiB（包含字段标识开销）。溢出明确失败，不截断。
- System/Primary 字段必须声明 Stable=true，Floating 必须为 false。稳定性目前是插件作者契约，宿主不通过执行隔离证明其正文不会变化；需要随档位变化的内容应放在 Floating。
- Prompt 必须纯且支持并发调用；控制面预览也会调用它。异常带插件身份包装并显示。未提供超时、进程隔离或取消不合作回调的机制。
- RequestParameter / ToolGate / Continuation / Verification 保留声明词汇，但注册时明确报 NotSupportedException，不执行任何机械效果。
