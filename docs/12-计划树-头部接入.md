# 12 · 计划树：头部接入

> 读者：写头的人。目标是把「剩余计划」画出来、让用户能改，并且**不要在头里重算核心已经算过的东西**。
>
> ⚠️ 本文只描述**接口与语义**。计划为什么要长成这样（只存剩余、推进即删除、提示词层停点）
> 属于设计决定，见 [`01` §3.5](01-会话设计.md) 的轴那一节与 `Kernel/Plan.cs` 的注释。

## 0. 一句话

**计划 = 这一批还剩什么。** 没有「完成」状态、没有进度百分比——
**推进一格就是把它从树里删掉**，所以「第一个叶子」天然就是「当前这一步」。

```
计划（剩余树）
▶ 读代码 [a]            ← 当前叶子（最先遇到的那个）
  正文：先把它读一遍
▸ 改代码 [b]            ← 分支（有子节点，不能执行）
  ○ 改一个文件 [b1]
    正文：改 ToolExecutor
```

## 1. 形状：三种记录共用同一份摘要

核心把普通计划与固定 T0 放在一个摘要里（`Kernel/Plan.cs` 的 `PlanSummary`，由 `PlanTree.Summary` 生成）：

```jsonc
{
  "active": true,                 // 普通树非空或设置了 T0
  "remaining": 3,                 // 只数普通可推进节点；T0 不计入
  "currentId": "a",               // 普通树当前叶子；普通树空时省略
  "currentTitle": "读代码",        // 当前叶子的标题；普通树空时省略
  "tree": [                       // 普通节点数组；普通计划空时省略
    { "id": "a", "title": "读代码", "body": "先把它读一遍", "children": [] }
  ],
  "t0": {                         // 用户设置的固定长期任务；不存在时省略
    "title": "长期维护",
    "body": "保持服务稳定，持续降低维护成本"
  }
}
```

`tree` 是模型可编辑、可推进的普通剩余计划；`t0` 是独立固定字段，模型能读，但普通 `plan` / `advance_plan` 工具不能设置或删除。用户/头用 `PUT /sessions/{id}/plan/t0` 设置它，用 `DELETE /sessions/{id}/plan/t0` 移除它；无效 title/body（或没有 T0 可删）返回 400 和 `error`。普通树为空时 `active` 仍可因 T0 存在而为 true，`remaining` 为 0。

⚠️ **`tree` 缺失 = 普通计划为空**；`t0` 缺失 = 没有固定长期任务。两者独立：即使 `tree` 缺失，仍可能有 T0。`WireJson` 会省略值为 `null` 的键。

⚠️ **`currentId` 是「普通树最先遇到的叶子」**，不是 T0，也不是运行时进度；推进一格就是从普通树删除它。

## 2. 读：三个入口，同一个形状

| 入口 | 什么时候用 | 载荷 |
|---|---|---|
| `GET /sessions/{id}/state` 的 `plan` | 打开会话时（**首选**，不用额外请求） | `{ active, remaining, currentId, currentTitle, tree }` |
| `GET /sessions/{id}/plan` | 只想要计划（例如面板单独刷新） | `{ sessionId, plan: <同一份摘要>, updatedAt? }` |
| WS 事件 `plan.updated` | 计划变了（模型推进 / 用户改 / 别的客户端改） | `{ sessionId, plan: <同一份摘要> }` |

⚠️ **这三个的 `plan` 逐字相同**，所以你只需要**一个**渲染函数（`renderPlan(summary)`）。
这条不是风格建议：本仓曾经一处给节点数组、一处给 `{nodes, updatedAt}` 对象，
于是同一个函数有一半路径把「有计划」画成「还没有计划」——那是把事实说反，不是显示错。

⚠️ `updatedAt` **只在 `GET /plan` 里有**：它答的是「这棵树什么时候动过」，
不是「现在是什么」，因此不进摘要（否则 `/state` 与事件都要跟着带上它）。

## 3. 写：一条 HTTP 端点 + 一条 WS 命令

两条**同语义、同解析器**（`PlanJson.ParseEdit`）。头用哪条都行；本仓的头用 HTTP。

```
PUT /sessions/{id}/plan        Content-Type: application/json
```

```jsonc
// 整份替换（空数组 = 清空）
{ "operation": "overwrite", "nodes": [ … ] }

// 插入（不给 parentId = 插到根；index 省略 = 追加到末尾）
{ "operation": "insert", "parentId": "b", "index": 0, "nodes": [ … ] }

// 删除（id 列表；连同子树）
{ "operation": "remove", "ids": ["b1"] }
```

```jsonc
// 成功
{ "ok": true }
// 被拒（400）——reason 是**给人看的一句话**，直接显示
{ "error": "叶子节点正文必须为 1..2000 个字符。" }
// 会话不存在（404）
```

T0 的移除走 `DELETE /sessions/{id}/plan/t0`（没有 WS 命令）：成功 `{ok:true}`，
被拒同样是 400 + `error`。它只清固定 T0，普通剩余树不受影响；两者都空时 `plan` 变成「没有计划」。

WS 那条命令的载荷多一个 `sessionId`：

```jsonc
{ "kind": "command", "id": "c1",
  "payload": { "kind": "session.plan", "sessionId": "s1", "operation": "remove", "ids": ["a"] } }
```

### 节点（`PlanNode`）

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | 可省 | 省略时核心**生成一个**（`Guid("N")`）。⚠️ **别自己造 id**——除非你要在后续编辑里引用它；全树必须唯一 |
| `title` | **必填** | 1..160 字符 |
| `body` | 叶子**必填** | 1..2000 字符。叶子的正文就是「这一步要做什么」，会原样进提示词；分支的 body 可选 |
| `children` | 可省 | 数组；空 = 这是一片**叶子**（可执行） |

### 三种操作的确切语义

| 操作 | 语义 | 会被拒的情况 |
|---|---|---|
| `overwrite` | 整棵树换成 `nodes`；**空数组 = 计划清空** | 结构不合法（见下） |
| `insert` | 插到根（不给 `parentId`）或某个**分支**之下 | `parentId` 不存在；**`parentId` 是叶子**（叶子不能再挂东西）；`nodes` 为空 |
| `remove` | 按 id 删（含子树） | 任一 id 不存在（**整条命令失败，不部分生效**）；`ids` 为空 |

结构上限：**64 个节点、最深 6 层**。超过就整条被拒——核心不截断、不丢节点。

⚠️ **删掉最后一个孩子之后，那个分支会自己消失**（不保留空的 `▸`）。
所以「删子节点」可能让父节点的 id 也一起从树里消失，头不要缓存旧 id 去再删一次。

## 4. 头的接入清单

1. **打开会话**：用 `/state.plan` 画（已经有树，别再多拉一次）。
2. **订阅 `plan.updated`**：用同一个 `renderPlan(p.plan)` 重画。
3. **画树**：分支用 `▸`、叶子用 `○`、当前叶子用 `▶`（依据 `currentId`）；
   叶子没有 `body` 时把它显眼地说出来（合法的树里不会出现，但**人改的 JSON 会**）。
4. **三个动作**直接打 `PUT`：整份覆盖 / 追加一个叶子 / 删掉选中的节点。
   失败时**把 `error` 原样显示**——那是核心给的人话，别自己翻译成「保存失败」。
5. **不要本地先改**：写完什么都别改本地状态，等 `plan.updated` 回来再画。
   本地先改的话，核心一旦拒绝，页面会先显示成功再被打脸。
6. **不要在头里判结构**（id 唯一、叶子要有正文、深度/节点数上限）：判宽判窄都会与核心分叉。
   头只做一件事——把用户写的东西原样交上去，把 `error` 原样显示出来。

## 5. 与轴的关系（决定模型会不会按计划走）

| 轴 | 值 | 对计划的影响 |
|---|---|---|
| `initiative` | `step` | **普通树有节点时**，尾块指明 `▶` 叶子就是当前步；完成后调用 `advance_plan`，核心只会移除普通树节点。普通树为空且有 T0 时不注入 step 指令，等待用户给下一步 |
| `initiative` | `standard` / `goal` | 不注入「当前步」指令。`goal` 可持续推进；只有普通计划为空时，`finish_goal` 才能把主动性拨回 standard。调用 `finish_goal` 仍是 goal 的显式结束条件 |
| `initiative` | `iterate` | 围绕 T0 长期任务反复工作；普通计划清空后核心自动将 mode 切回 plan，并在尾块要求参考 T0 规划下一段。不能调用 `finish_goal`，也不能请求离开 iterate 规划/行动循环 |
| `mode` | `plan` | 多一句「现在只调整计划，不动手执行」。`write/update/delete/mkdir/git_write` 被模式闸硬拒，与权限档位、记忆批准无关；`shell/dotnet_build/dotnet_test/path` 按用户裁定不被此模式闸拦 |
| `mode` | `act` | 按普通计划执行（默认）；在 `goal` 里普通计划完成后，可用 `switch_plan_mode(mode=act, reason=...)` 请求退出 plan，用户批准后切换 |
| `switch_plan_mode` | `plan` | 进入规划模式不询问用户；必须填写 reason |
| `switch_plan_mode` | `act` | 在非 iterate 且普通树为空（goal）或 step/standard 里确需动手时发 Permission 卡；任意 permission 档位均询问、不提供记忆选项；卡上展示 reason |
| `permission` | `off` | 常规工具仍全拒；`switch_plan_mode` 不经过 permission 闸，以便它能按自身语义提出 Permission 询问 |
| `permission` | `readonly` 及以上 | `plan` / `advance_plan` 可用；只读档本来就能改普通计划，这是设计意图 |

⚠️ **计划和轴是两件事**：计划说「还剩什么」，轴说「此刻按什么规矩做」。
头不要把「有没有计划」映射成任何一种轴值——用户可能一边 `goal` 一边有树。

## 6. 已知边界（都是**决定**，不是待修）

- **没有完成态**：推进即删除，删掉的节点不会留在任何地方（历史上仍能从 `history` 里看到那条 `advance_plan` 调用与它的结果）。
- **没有进度百分比**：`remaining` 是剩余节点数，不是「完成了几分之几」——计划随时可重排，分母不稳定。
- **没有合并语义**：用户改计划与模型改计划同时发生时**后写的赢**（每次编辑是一次整树替换，
  不会按节点三方合并）。⚠️ 具体地：模型在某一步里改了计划（`planChanged` 为真），
  而用户在**那一步的过程中**也提交了编辑 ⇒ 用户那次会被模型那一步的结果覆盖。
  头能做的是：编辑被拒/被覆盖时如实反映 `plan.updated` 回来的树，不保留「我刚改过」的假设。
- **不跨会话**：每棵计划属于一个会话，没有项目级计划。
- **不进历史记录**：计划与 T0 住在 `state.json`（普通剩余树从格式版本 11 起，固定 T0 从格式版本 12 起）；模型看到的是**尾块里现渲染的那一份**，不是一条历史事件。⇒ 改计划不会污染对话记录，也不会被压缩裁掉。
- **模型侧的两个工具**（`plan` / `advance_plan`）与头走**同一套语义**：
  工具只判参数、回一句话，真正的落地在**那一步结束**时由推进器做。
  ⇒ 头看到 `plan.updated` 的时刻是**步末**，不是工具调用的那一刻。

## 7. 自检（不装头也能验）

```bash
# 建一棵树（不带 id，让核心生成）
curl -sX PUT localhost:17988/sessions/<sid>/plan -H 'content-type: application/json' \
  -d '{"operation":"insert","nodes":[{"title":"读代码","body":"先读一遍"}]}'

# 读回来（形状与 /state.plan 相同）
curl -s localhost:17988/sessions/<sid>/plan

# 推进掉当前叶子（模型侧同一个判据：必须给对 currentId）
curl -sX PUT localhost:17988/sessions/<sid>/plan -H 'content-type: application/json' \
  -d '{"operation":"remove","ids":["<currentId>"]}'
```

⚠️ **一次改一条**：`PUT` 是整条命令原子生效的，`nodes` 里的结构错误会让**整条**被拒
（例如三个节点里有一个叶子没写正文，另外两个也不会落下）。
