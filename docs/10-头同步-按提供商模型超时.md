# 头同步清单：按提供商配置的**模型调用超时**

> 适用核心版本：`provider.timeoutSeconds` 上线之后（本次改动）。
> 面向：**头**（`src/Lilara.Head`）的维护者。核心已经改完，这份只讲「头要跟着改什么」。
> ⚠️ 本文是**交接单**，不是设计文档：里面每条都对应一个可验收的动作。

---

## 0. 一句话

核心现在允许**按提供商**配置「一次模型调用最多等多久」，以前这个数字是隐式的：
OpenAI 兼容链路被 .NET `HttpClient` 的 **100 秒**掐死（谁也改不了），Claude 链路交给 SDK 默认值。
头要做三件事：**让用户能配这一格**、**看得见这一格当前是多少**、**超时失败时能一眼认出来并就地改大**。

---

## 1. 为什么要改（先看这三个现场）

1. **100 秒掐掉的会话，现场只留下一句看不懂的话。**
   慢推理 / 大 `max_tokens` / 推理型模型在非流式调用下一次跑 100 秒以上并不罕见。
   到了 100 秒，`TaskCanceledException` 被包成一句「模型调用失败：…」，**没有一个字说是本地超时**。
   于是所有人先去查上游、查 key、查网络——而真正该改的是本地那一格。
2. **它还会被重试掩盖。** 超时是**瞬态**，`RetryPolicy` 会再试 10 次（退避合计约 35.6 秒）。
   结果是一步卡住十几分钟、日志里 11 条失败、账面看像「上游一直不稳」，实际是**每次都在同一个本地秒数上被掐**。
3. **不同提供商速度差一个数量级**，一个全局数字必然错：快的被拖成「挂死」，慢的被砍成「超时」。
   ⇒ 所以这一格住在**提供商**上，不住在会话 / 全局配置里。

---

## 2. 线上契约增量（只有这几处）

### 2.1 `GET /providers` —— 每个提供商多一格

```jsonc
[
  {
    "id": "local",
    "protocol": "claude-messages",
    "defaultModel": "deepseek-flash",
    "endpoint": "http://127.0.0.1:15721",
    "authScheme": "bearer",
    "modality": "vision",
    "models": ["deepseek-flash", "deepseek-pro"],
    "timeoutSeconds": 600,        // ← 新增：一次模型调用的超时（秒）
    "hasApiKey": true
  }
]
```

- ⚠️ **没配的时候这个键根本不存在**（`WhenWritingNull` 被全局打开，与 `endpoint` / `authScheme` / `models` 同一族）。
  ⇒ 头必须判 `p.timeoutSeconds` 的真假，**不要** `p.timeoutSeconds || 100` 然后显示成「100 秒」——
  那会让用户以为「配过 100」，而真相是「没配，走协议默认」。
- 没配时两条链路的默认值**并不相同**（OpenAI 兼容 100 秒 / Claude 由 SDK 定），
  所以头**不要替核心编一个统一默认值显示**，显示「（默认）」即可。

### 2.2 `provider.upsert` —— 多一个可选键

```jsonc
{ "kind": "provider.upsert", "id": "local",
  "apiKey": "sk-…",              // 省略 = 保留旧 key（新 provider 必须给）
  "model": "deepseek-flash",
  "protocol": "claude-messages",
  "endpoint": "http://127.0.0.1:15721",
  "auth": "bearer",
  "models": ["deepseek-flash", "deepseek-pro"],
  "timeoutSeconds": 600 }        // ← 新增：省略 / 键缺失 = 保留旧值
```

| 键 | 类型 | 语义 |
|---|---|---|
| `timeoutSeconds` | 数字（整数） | 一次**模型调用**的超时，秒。**省略 = 保留旧值**（与 `apiKey` / `models` 同一条语义） |

- 合法区间 **1..1800**（秒）。越界 ⇒ `ack{accepted:false}`，`reason` 是
  `` `--timeout` 要在 1..1800 秒之间（给的是 N）。`` —— 核心**不夹紧**，别指望它替你把 0 修成 1。
- 成功回执的 `note` 仍然是**生效的协议名**（没有为这一格新增措辞，别去解析它）。

### 2.3 控制台等价命令（给「粘贴到核心控制台」之类的帮助文案用）

```
provider set <id> --timeout <秒>
```

### 2.4 没有变的东西（省得去找）

- **没有新端点、没有新事件、没有新字段在 `/sessions` / `/state` / `/history` 里。**
- `/provider-schema` **没变**（也就意味着：合法区间 1..1800 **今天不在线上**，见 §6 第 2 条）。
- `retry.attempt` 事件形状没变，但**它现在更常被看到**：超时是瞬态，会触发它。

### 2.5 失败文案变了（要能认出来）

超时失败现在长这样（两条链路一致）：

```
模型调用超时（600 秒）。慢模型可以给该提供商调大 timeoutSeconds（`provider set <id> --timeout <秒>`）。
```

- 它**仍然走 `error` 事件**（业务失败，不是 `rejected`）。
- 与它形成对照的两句（**别混**）：
  - 连接类失败：`模型调用失败：<底层原话>`
  - 用户中断：**不产生 `error`**（`interrupt` 不算失败）
- 十次重试用尽时，末尾会多一句：`（已自动重试 10 次，仍然失败）`。

## 3. 头要做的四件事（可验收）

### ① 提供商编辑表单：多一格

- 标签建议「调用超时（秒）」，`type=number`、`min=1`、`step=1`，等宽字体（与端点一致）。
- 占位文案：「留空 = 协议默认（OpenAI 100 秒；Claude 由 SDK 定）」。
- **留空 ⇒ 整个键都不发**（与密钥同一语义）。⚠️ 不要发 `0`、不要发 `null`：
  核心把非数字/缺失都读成「保留旧值」，而 `0` 会被**拒绝**（越界）——两种都不是「默认」。
- 前端先做一次整数校验，非整数当场报错（`30s` / `10分钟` / `1.5` 都算错）。
  为什么必须在头里拦：核心把「不是数字」读成「没给」⇒ 会**静默保留旧值并回 ✓**，用户以为改了。
- **老核心兼容**：如果 `/providers` 里没有这个键，表单照旧工作（这一格为空，保存时不发这个键）。

### ② 只读摘要：让人一眼看到当前值

在提供商卡片的键值区加一行，例如：

| 标签 | 有值时 | 没配时 |
|---|---|---|
| 调用超时 | `600 秒` | `(默认)` |

⚠️ 不要显示成 `100 秒`（见 §2.1 第一条）。

### ③ 超时失败的呈现：给一条**就地改大**的路

最小要求：`error` 事件的文案原样显示（今天的 `renderMeta("✗ " + p.message, "error")` 就够）。

**建议**（今天没做，做不做你定）：认出 `模型调用超时（N 秒）` 这一句时，额外给一个按钮
「把这个提供商的超时调到 2 倍」，点了就发一条 `provider.upsert{ id, timeoutSeconds: N*2 }`。
判据**不要**用整句字符串匹配——用**稳定片段** `模型调用超时（`，并把括号里的数字解析出来；
核心改措辞时这条会一起失效，所以只在它能拿到数字时才出按钮。

### ④ 重试附注：把「本步生效的超时」带上（可选，但很有用）

头已经在处理 `retry.attempt`（「重试 N/10 · X 秒后再试」）。建议在同一个附注里补一句
「单次上限 600 秒」——数据从 `/providers` 那份缓存里取（会话的 providerId 在 `/state` 的 `spec.model.providerId`）。
理由：这一步会连着失败 11 次，而**唯一能解释「为什么每次都失败在同一个时间点」的数字**就是它。

---

## 4. 不许做的（五条陷阱，都踩过或差点踩）

1. **不要用 `0` 表示「默认」**：核心会 `rejected`（越界）。默认的唯一表达是**不发这个键**。
2. **不要在前端自己重试或截断请求**：重试与退避只有一处（核心的 `RetryPolicy`）。
   头再套一层 = 一次用户操作打出几十次上游请求。
3. **不要把它当成「步超时」或「询问超时」**：
   - 步超时：**没有**这个东西；
   - 询问超时是 `session.create` / `session.configure` 的 `askTimeoutMinutes`（等用户回答），完全另一件事。
4. **不要把「缺键」读成 100**（§2.1）：会显示一个用户没配过的数字。
5. **不要把自检（`provider.test`）的 10 秒和这一格混为一谈**：
   探针有自己**固定 10 秒**的总预算，配置 600 也不会让它等 600 秒；
   反之，端点慢导致自检「没在预算内通」**不代表**会话里也会超时。文案上别把两者写进同一句。

## 5. 验收清单（照着敲一遍）

前置：一个**慢**提供商（或把自己指向一个会拖 2 分钟的假端点）。

| # | 动作 | 期望 |
|---|---|---|
| 1 | 打开提供商卡片 | 键值区有「调用超时」，没配的显示「(默认)」，**不显示 100** |
| 2 | 编辑 → 超时填 `600` → 保存 | 回执 `accepted:true`；重拉 `/providers` 里 `timeoutSeconds: 600`；卡片显示「600 秒」 |
| 3 | 编辑 → 超时填 `0` → 保存 | 卡片上出现红字 `--timeout 要在 1..1800 秒之间…`；盘上**没变**（重拉还是 600） |
| 4 | 编辑 → 超时填 `30s` → 保存 | **前端就报错**，命令没发出去（用浏览器 Network/WS 面板确认） |
| 5 | 编辑 → 超时清空 → 保存 | 键**不发**；`/providers` 里 `timeoutSeconds` 这个键**消失**；卡片回到「(默认)」 |
| 6 | 把超时改成 `1`，向慢端点发一条消息 | 约 1 秒后出现 `模型调用超时（1 秒）。…`，随后看到 `retry.attempt` 一条条来（最多 10 次） |
| 7 | 上一步期间点「停止/中断」 | 立刻停；**不**出现「超时」那句（取消不是超时） |
| 8 | 老核心（没有这个键） | 表单这一格为空且可保存其余字段；保存**不发**这个键；卡片不崩 |

## 6. 今天还没有的两件事（别在头里绕过去）

1. **没有「清回默认」的入口。** `provider.upsert` 里「省略 = 保留」与「显式清空」表达不出区别，
   和 `askTimeoutMinutes` 是同一个缺口（`03` §14 #13 那族）。⇒ 头**不要**发明 `timeoutSeconds: null` 或 `0`
   去表示清空，那两条会被读成「保留」/「拒绝」。
2. **合法区间（1..1800）不在线上。** `/provider-schema` 没有暴露它。
   ⇒ 头若想在表单上写「1..1800」这种提示，**请先让核心把它加进 `/provider-schema`**，
   别在前端手抄数字——本仓已经因为手抄协议表 / 认证方式栽过两次（见 `04` §1.2）。
   在那之前，头只做「整数」校验，区间交给核心的 `reason` 显示。

## 8. 一句话给用户看的（可放进头的帮助/提示）

> 每个提供商可以单独设「一次调用最多等多久」（秒）。慢模型被 100 秒掐掉时，
> 把这一格调到 600 左右通常就够了；设置只影响**下一次**调用，不用重建会话。
