# 插件与内部结构

> 本文是**核心的内部组成**与**插件契约**——两者强耦合，一处处置。
> 会话本体见 [`01-会话设计.md`](01-会话设计.md)，调度见 [`02-多会话调度.md`](02-多会话调度.md)，接口见 [`03-控制面协议.md`](03-控制面协议.md)。

---

## 1. 内部结构

```
核心
├─ 注册表        provider / 项目 / 会话（索引，只读为主）
├─ 插件宿主      加载 · 收集贡献 · 分发钩子          ← 本文
├─ 资源管理器    声明 / FIFO / 解除阻塞              ← 01 §12
├─ 步调度器      决定下一个推进谁                    ← 02
├─ 推进器        渲染 → 调用 → 执行 → 落盘           ← 01 §3–§6
├─ 协议适配器    **内建，焊死**（Claude / OpenAI ×2） ← §1.2
└─ 控制面        WS + HTTP（头 · 控制台）            ← 03 / §1.1
```

**插件宿主是唯一的耦合点**：它收集全部贡献，各组件**从收集结果里读自己那一份**——调度器读驱动源，推进器读工具表与提示词，控制面读控制点。

> **没有任何组件直接认识插件。** 这是「知识与责任同处」（[`00` §1.3](00-设计哲学.md)）在结构上的样子。

### 1.1 控制台：控制面的第二个客户端

核心是**常驻的控制台程序**：附着一条命令面（标准输入），**启动即进交互循环，直到显式退出**——不是"跑完参数就退"的一次性工具。

⚠️ **它是控制面的一个客户端——与头同一个面，不是第三个面。**

```
核心
├─ 控制面        WS + HTTP
│    ├─ 头       观察者 + 命令源
│    └─ 控制台   只有命令源（stdin 是它的入口）      ← 本节
└─ 插件宿主                                        ← §2–§7
```

**它不是独立的面**，因为**控制台从不直连核心内部**——它把命令喂进控制面的通道，与头**走同一条路、同一套命令集、同一个回执**。所以：

| | 约束 | 由什么保证 |
|---|---|---|
| **不是头** | **没有视图**：同步收发（问 → 答 → 完），**绝不订阅、绝不流式渲染** | ⚠️ **一张没有状态的地方，挂不住视图**——结构性，非纪律性 |
| **不是一次性工具** | 常驻交互 | 它就是进程本身 |
| **不新增鉴权面** | 本机进程即可信（[`03` §10](03-控制面协议.md)） | 同一个信任模型 |
| **不新增并发面** | **控制台天然独占**：核心本设备唯一（[`README`](README.md)）⇒ 不存在第二个控制台 | 母约束的推论 |

**"命令投递即返回"在本地退化成"同步拿回执"** —— 投递与返回都是内存操作，所以交互体验是 RPC 式的，**而协议语义一点没变**。这是 [`03` §3](03-控制面协议.md) 那个设计的一次免费兑现：正因为核心不等结果，多一个客户端不需要任何新机制。

⚠️ **它能做的，就是头能做的**——同一份命令集（[`03` §3](03-控制面协议.md)），不多一条：

| 用途 | 命令 |
|---|---|
| **当纯手动头用** | `session.send`（塞消息）· `session.start`（启动循环）· `session.activate` + 快照 HTTP（**检查消息**——读走快照，不走订阅） |
| **止血**（比头更常被用到） | `session.interrupt` · `approval.respond` · `claim.release`（**本就是"模型失控时的逃生口"**） |
| **引导**（无头时唯一入口） | `provider.upsert` · `session.create` |

> **「核心不关心头在不在」推到底 ⇒ 核心不该关心控制台在不在，也不该依赖它在。**
> ⚠️ 反过来说：控制台**关掉不影响任何东西**，核心照常自跑（[`README`](README.md) 硬约束「无头也能自跑」）。

### 1.2 协议适配器：焊死在代码里，不做插件

> **它是核心的一部分，跟协议走，不跟用户走。**

| | 理由 |
|---|---|
| **收益极低** | 一时半会就这仨协议（Claude Messages / OpenAI Chat / OpenAI Responses），**没有拓展需求** |
| **且是核心能力** | 做成可卸载的插件，等于把"能跑"变成可选项——**装错一个插件能让 agent 失联** |

⚠️ **与「MCP = 适配器插件」不矛盾，是镜像的两端**（[`00` §5](00-设计哲学.md)、§4）：

| | 方向 | 归属 |
|---|---|---|
| **上游协议适配器** | 出（canonical → Claude / OpenAI） | **内建**（本设备必备能力） |
| **MCP 适配器插件** | 入（MCP server → 我们的插件契约） | **插件**（引入外部能力） |

**一出一入，一个焊死一个外挂**——因为**出去的协议是产品的形状，进来的能力是用户的形状**。前者不该可换，后者必须可换。

### 1.3 核心是空壳：内容全由插件提供

> **核心提供机制与装配位；插件提供全部内容。**（[`00` §1.3](00-设计哲学.md) 机制与策略分离）

⚠️ **修正一个曾有的设想**：曾考虑让核心自带「最核心的插件」（内置工具 + 系统提示词）。**不做。**

| | 核心自带 | 由插件提供 |
|---|---|---|
| 提示词内容 | ❌ | ✅ **含系统提示词** |
| 工具 | ❌ **一个都没有** | ✅ 全部 |
| 装配位与装配机制 | ✅ | —— |
| 协议适配器 | ✅（§1.2） | —— |

**三条推论**：

1. ⚠️ **「没有任何插件」是完全合法的形态** —— 那就是**纯 chat**。而**裸核心连系统提示词都没有**——块数恒定说的是「最多各 1 块」，**不是说一定非有不可**。没有贡献者就没有块，这和"多个插件的贡献必须合并成 1 块"是同一件事的两头。
2. **ALP 需要显式结束循环，本项目不需要** —— 循环的停止条件是**主动性轴**（[`01` §3.5](01-会话设计.md)），是**核心的**预设值，**不是某个插件提供的**。所以拿掉插件不会让循环失控。
3. **`spec.json` 是唯一必须非空的东西** —— 会话至少要能回答"这一步是哪个模型跑的"（[`01` §7.2](01-会话设计.md)）。插件清单可以是空的，provider 不行。

⚠️ **由此，「核心自带哪些工具」这个悬而未决的问题消失了** —— 答案是没有。 [`01` §9](01-会话设计.md) 的「内置工具」一词**随之作废**。

⚠️ **工具不是独立实体**（修正 [`01` §9.1](01-会话设计.md) 的「工具 / 插件注册表」）：

> **工具是插件的贡献，不是兄弟概念。工具表是派生的。**

省掉一整套并行的注册与生命周期管理。MCP 工具同样派生自 MCP 适配器插件（§4）。

## 2. 插件 = 声明 + 回调

> **贡献是数据，钩子是行为。** 数据在加载时收集，行为在定义好的相位上被调用。

这是「数据与行为分离」（[`00` §1.2](00-设计哲学.md)）在插件层的复现。推论：

> **插件不是"被调用的"，是"被收集的"。**

## 3. 五个贡献面

⚠️ **前四个各自覆盖「一步」的一段相位**（`04` §6 的相位图上，驱动 / 渲染 / 执行各有着落；**模型调用与落盘是核心自己的**，不对外开放）：

| 面 | 给谁的 | 相位 | 挂在 |
|---|---|---|---|
| **工具** | 模型的**手** | 执行 | 执行 / 渲染 / 优化 / **取消**钩子 · 权限类别 |
| **提示词** | 模型的**眼** | 渲染 | 头槽位两块 + 尾槽位字段 |
| **控制点** | 人的**手** | 任意 | 控制面命令（[`03`](03-控制面协议.md)） |
| **驱动与指令** | 循环的**扳机与轨道** | 驱动 | 驱动源 · `pendingDirectives` |

**第五个是横切面：事件订阅** —— 它**不对应任何相位**，是**只读观察者**。与控制点成对：**控制点是「人 → 插件」，订阅是「插件 → 人」**。通知、遥测、日志都挂这儿。

**两个统一**：

- **轴 = 控制点的特例** —— 命令固定为 `setAxis`。插件加轴不需要新机制
- **强制调用 = 一条指令** —— [`01` §11.5](01-会话设计.md) 的 `pendingDirectives` 已是通用形态，贡献一条即可

### 3.1 控制点：声明数据，头渲染

> ⚠️ **插件不带 UI。UI 全是头的事。**

```
插件声明：{ id: "clearCache", label: "清空缓存", 参数: [...] }
头渲染成：按钮 / 下拉 / 开关          ← 头自己决定
```

**"插件提供按钮"存在于声明层，不存在于代码层。** 真要做定制 UI，得与头单独协商——**不划算，不做**。

### 3.2 取消钩子

工具的第四个钩子是**取消**（见 [`00` §5](00-设计哲学.md) / [`01` §9](01-会话设计.md)）。

⚠️ **它必须有**：[`03`](03-控制面协议.md) 有 `session.interrupt`——**打断在工具层没有落点的话，在飞的调用怎么办？**

## 4. MCP = 适配器插件

> **MCP 服务器就是一个插件，其贡献恰好由远端提供。**

⚠️ **不存在「MCP 子系统」。** 这与上游协议适配器**完全镜像**：

| | 方向 | 干什么 |
|---|---|---|
| **上游协议适配器** | 出 | 我们的 canonical → Claude / OpenAI |
| **MCP 适配器插件** | 入 | MCP server 的能力 → 我们的插件契约 |

**同一个形状，相反方向。** 收益立刻出现：

- MCP 工具走**同一套**生命周期、权限类别、渲染策略 ⚠️ —— 但**钩子只有「执行」**：**渲染 / 优化 / 取消不在 MCP 原语里**，那三个走核心侧默认策略
- MCP 的 `prompts` 原语天然映射到**提示词贡献**——它本来就有的东西
- **反过来也成立**：想要隔离，就**把自己的插件包成 MCP server**。这是"带外插件"的标准形态

⚠️ **MCP 掉线不能改工具表** —— 工具表在最前，改它全废。沿用 [`01` §3.5](01-会话设计.md) 那条：**工具仍在，调用时拒**。掉线只是调用失败。

## 5. 插件形态与信任

| | **进程内** | **MCP** |
|---|---|---|
| 信任 | **完全信任**（能碰核心内存） | 隔离（带外） |
| 适用 | 自建插件、需要钩子的 | 异构语言、第三方、想要隔离的 |
| 能力 | 全部五个面 | 取决于 MCP 原语覆盖（工具 / prompts 有；**控制点、订阅、渲染 / 优化 / 取消钩子没有**） |

⚠️ **诚实地说：装一个进程内插件 = 把核心交给它。** 不粉饰。

**权限类别**（[`01` §3.5](01-会话设计.md)）：MCP 声明不了自己的类别 → **未声明即取默认类别**，默认取 **`Writing`**。

| 默认取 | 后果 |
|---|---|
| `ReadOnly` | ❌ 未知工具可能在标准档**静默删库** |
| `Destructive` | ❌ 只读的 MCP server 在**标准档被整个拒掉**，MCP 不可用 |
| **`Writing`** | ✅ 标准档**问一句**（可用），授权档放行 |

⚠️ **要认的洞**：一个真破坏性的工具若被误判为 `Writing`，在**授权档会不询问直接跑**。这是"不知道就打中档"的代价。

## 6. 钩子与相位

```
一步 = 驱动 → 渲染 → 调用 → 执行 → 落盘
        │      │      │      │      │
        │      │      │      │      └─ 优化钩子（在 GC 窗口）
        │      │      │      └─ 执行钩子 / 取消钩子
        │      │      └─ （模型调用）
        │      └─ 渲染钩子（纯函数）· 提示词贡献
        └─ 驱动源（插件可产生）
```

## 7. 热重载

**要做，而且它本来就是「先制造前缀失效，再顺手做手术」的又一例**（与 `compact`、`release` 同族）。

### 7.1 快照已经解决了最难的部分

⚠️ 本来会担心：插件升级 → 渲染实现变了 → 历史里工具结果的**渲染字节变了**，而且从**最旧的那个**开始变。

**不用新增机制。** [`00` §5](00-设计哲学.md) / [`01` §9](01-会话设计.md)：**快照 = 上次实际喂给模型的渲染产物**。所以指纹一致时用的是**旧快照，新渲染代码压根不被调用**。

### 7.2 代价可精确预测

| 插件改了什么 | 破前缀吗 | 因为 |
|---|---|---|
| **工具的渲染实现** | ❌ **不破** | 快照钉住 |
| 工具的权限类别 | ❌ | 不在请求里 |
| 浮动贡献 | ❌ | 本来就每步在变 |
| **工具集增删** | ✅ 破 | 工具表在**最前** |
| **提示词贡献** | ✅ 破 | 在**头槽位** |

> **工具插件可以随便升；提示词插件升级就是它本来的目的。**

### 7.3 五条机制

1. **贡献集合每步取一次快照** —— 与 `now` 冻结同步开始（[`01` §3.2](01-会话设计.md)）同一个道理。否则渲染不再是纯函数：**半新半旧 → 每步都破前缀**
2. **顺序一并冻结** —— 快照里不只有**集合**，还有**顺序**（[`01` §3.1](01-会话设计.md)）。冻结之后"瞎变"不是被规则禁止，是**结构上没有东西可以变**
3. **前缀指纹** —— `hash(工具表 ∥ 系统块 ∥ 首要块)`，**每步比对**：

   > **指纹变了 ⇔ 缓存必然失效。** 不是"猜会失效"，是**同义反复**。

   它**顺手吃掉"什么算变更"的枚举**——不需要枚举，也就不会漏。而且它是**精确的**：只贡献浮动字段的插件变了，**指纹不变**（浮动块本来就不在缓存里），不误判。

   ⚠️ **只覆盖重建的部分** —— 历史是追加的（结构上不破前缀），GC / release / compact 是显式事件。
   ⚠️ **住内存，不落盘** —— 它是**预测**不是正确性依据。丢了 ⇒ 当作"冷"，而这**几乎必然是对的**（时间都过去了）。与 [`00` §5](00-设计哲学.md) 那个工具结果指纹**同一个定位**：优化的输入，不是正确性的机制。
4. **切换发生在步边界** —— 绝不在步中途
5. **在飞的调用钉住旧版本** —— 引用计数，最后一个在飞调用结束后才卸载。**失败保持旧版本**（原子切换，绝不半加载）

### 7.4 它打开 GC 窗口

前缀失效 = 唯一的免费改写窗口（[`00` §0](00-设计哲学.md)）。所以重载是**又一个回收时机**——与 `compact` / `release` 同族。
