# 浮动上下文：落盘、取代、变化才更新

> 状态：**方案定稿，未实现**（2026-10-23）。三件事必须**一次做完**——只做一半会得到
> 「请求里叠加两份读数」或「协议里出现无主的 tool_result」，两种都是坏形状。

## 0. 目标（一句话）

让「这一步我确实读到过环境」在**记录**里成立，同时让旧读数**在视野里只占一行**，
并且**只在轴值变化时**才产生新的一份——于是没有「每步反复出现」这种可被解释成异常的节律。

## 1. 五处改动

| # | 落点 | 改什么 |
|---|---|---|
| 1 | `Stepper.StepAsync` | 合成对**落盘**（`floating-{turn}-call/result` 进 `AppendEvents`），不再是「只活在这一次请求里」 |
| 2 | `TimelineRender.Render` | 渲染期**取代**：除最新一份外，其余浮动对**整对**从视野里去掉；最新那份的首块前加一行注记 `[floating_context · 第 a–b 步的读数已取代]` |
| 3 | `Stepper.StepAsync` | **变化才注入**：拿「最近一份落盘读数的轴值」与「本步轴值」逐字段比；相同 ⇒ 不产生新对（也不落盘）；不同 ⇒ 取代 + 注入。**会话第一步无条件注入** |
| 4 | `FetchTool` / `ContextCompaction` | 排除 `floating-` 前缀的 id：**旧读数不可取回**（理由不是省 token，是过期档位复活会导致按旧权限/安全档位行动）；压缩摘要里不写「我检查过环境」 |
| 5 | `FloatingContextTool.Description` | 换成**条件式**规则：「上下文里没有任何有效块时才调用」；删掉「不必再调」这类态度句。自调返回正常读数（那一格就是「确实没有块」的场景） |

## 2. 判据（必须只有一处）

「有没有效块」与「轴值变没变」是**同一个问题的两半**：都靠「最近一份块里的轴值 vs 当前轴值」比一次。
⇒ 抽成一个谓词，`Stepper` 与 `TimelineRender` 共用；两处各写一遍必然漂。

## 3. 已知取舍

- **「每步都做」的证据消失**：因此**不要**再靠步号去消解「预判」叙事——降频率本身就是解。
  步号可以保留在框架头（`[floating_context 步 N]`），它是坐标，不再是证据。
- **纯 chat 会话**（无工具表，尾块退回槽位）必须走同一套判据，否则两条路语义分叉。
- **`Turn` 与落盘顺序**：浮动对要落在「模型回复 + 其工具结果」**之后**，且配对完整
  （`tool_use` 紧跟 `tool_result`），否则部分上游 400。

## 4. 测试要钉的

1. 轴不变走两步 ⇒ 记录里**只有一对**浮动事件（第二步没有新增）。
2. 轴变一步 ⇒ 记录里两对；渲染后视野里**一份有效读数 + 一行取代注记**。
3. `fetch(floating-…)` ⇒ 拒绝；`compact` 摘要里不含浮动内容。
4. 无工具表的会话 ⇒ 行为与有工具表时**同判据**（尾块在槽位里，取代规则一致）。
5. 配对完整性：渲染产物里不出现「无 `tool_use` 的 `tool_result`」。

## 5. 为什么不能只做一半

- 只落盘不取代 ⇒ 历史里每步一份完整读数，**就是最初要消灭的膨胀**。
- 只取代不落盘 ⇒ 取代没有对象（盘上没有旧块），退化成今天的形态。
- 落盘 + 取代但不改「变化才注入」 ⇒ 仍然每步一份，噪音不变，只是被折叠。
- 改了注入频率但不排除 `fetch` ⇒ 旧档位可被取回并当真。
