## 六、第一个来回：实测跑通了

⚠️ **这是一次手工实测，不是自动化测试**——它不跑在 `dotnet test` 里（真打网络）。

**结论：核心的端到端链路是通的。「一次都没成功」是配置，不是代码。**

```
2026-10-05 · HEAD ae66b88 · 沙箱数据根 E:/Workspace/Temp/lilara-alc-e2e（未碰真实 ~/.lilara）

provider set local --key PROXY_MANAGED --protocol claude-messages \
  --model deepseek-flash --endpoint http://127.0.0.1:15721 --auth bearer
session create
hello

⇒ ✓ 提供商 'local' 已保存（claude-messages）。
    端点 http://127.0.0.1:15721（来自 provider 配置）      ← 「生效端点必须打印」这条硬约束生效
  ✓ 会话 9eac068ae472 已创建。
  ⏺  Hello! How can** I help you today?

落盘核实：state.json turn 0 → 1；history.jsonl 两行（user "hello" / model[reasoning+text]）
```

**根因**（两次叠在一起）：

1. **配置**：真实数据根两个 provider 的 `endpoint` 都指着 `http://localhost:5129/`，而**那个网关没在监听**
   （`netstat` 只有 15721）。用户消息先落盘、调用失败 ⇒ `history.jsonl` 只有 user 那行、`turn` 停在 0。
   **5129 起来之后仍不通**，因为 `apiplan.json` **没写 `authScheme`** ⇒ 默认 `api-key`（`x-api-key`），
   而 **5129 只认 `Bearer`**（实测：`x-api-key` + 真 key ⇒ 401；`Bearer` + 真 key ⇒ 200）。
2. **代码**（`95c0be3` 修）：5129 的 401 回 `{"error":"Authentication required"}`——
   **`error` 的值是字符串**，而 Anthropic 规范要求它是**对象**。官方 SDK 去读 `.error.type`
   ⇒ 内部 STJ 抛 `requires an element of type 'Object' …` ⇒ 它不是 `AnthropicException` 子类
   ⇒ 落进 `Describe` 的兜底，**把机器话原样透传**。⇒ **任何 401 都变成一句读不出原因的话**。
   现已翻成人话，并指向最可能的原因（端点 / auth 方式）。

⚠️ **`ANTHROPIC_BASE_URL` 指着的 `127.0.0.1:15721` 也是一个活的 Anthropic 形状端点，且
`x-api-key` 与 `Bearer` 两种鉴权都收**（实测）——拿它做本地联调最省事。

⚠️ **2026-10-05 已修**：`~/.lilara/providers/apiplan.json` 补了 `"authScheme":"bearer"`
（改前备份在 `~/.lilara/providers.bak-20261005-160500/`）。
⇒ 真实数据根上 `hello` 往返成功：`turn 0→1`、已挂账三天的会话终于走完一步。

⚠️ **没被自动化覆盖的部分**：这一条链路（真的构造请求 → 真的发 → 真的映射响应 → 真的落盘）
**只在手工跑到时被验证过**。`dotnet test` 里没有等价物——适配器测试全都是对着假 HTTP / 纯函数做的。

## 七、怎么重新核对这份文件

这份文件会腐（它已经是一份「快照」了）。**重新核对的方法是可执行的**：

1. **某个子系统做没做**——在 `src/` 里 grep 该子系统的关键词。零命中就是没做。
2. **某个命令通不通**——查**四条线**是否都接上：
   `CoreCommand.cs`（record）→ `CommandDispatcher`（分支）→ `ControlServer.ParseCommand`（线上）→ `CoreCommandParser`（控制台）。
   **任何一条缺了，那个命令就是死的。**
3. **某个事件活不活**——查**生产者**（`CommandDispatcher` / `EventBus` 里真的 `Publish` 了吗）与**消费者**（`head/wwwroot/app.js` 里真的处理了吗）。缺一头就是死投递。
4. **`00` §8 的十条作废设计有没有复活**——按关键词搜代码与文档（2026-10-05 那次：**无一复活**）。

⚠️ **别从注释推断现状**——注释会腐，而且它**不会报错**。`Kernel/Axes.cs` 就曾写着一句
「头的下拉今天还不存在（`head/` 里没有任何轴字面量）」，而头里当时**已经有三处**轴字面量了。
