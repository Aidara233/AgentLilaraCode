# 后台任务、自动回报与统一等待

进程工具 `shell`、`dotnet_build`、`dotnet_test` 接受 `background` 与 `timeoutSeconds`。后台启动立即返回 `job-…` id，子 agent 则使用 `spawn` 返回的会话 id。两类 id 都可直接交给 `wait(task=…)`，无需查表换算。

## 等待

```text
shell(command="…", background=true, timeoutSeconds=300) → job-…
wait(task="job-…")
spawn(task="…") → 子会话 id
wait(task="子会话 id", timeoutSeconds=30)
```

省略等待的 `timeoutSeconds` 会一直等到结束；提供时限则到点返回状态，任务继续运行。等待接受 1..86400 整数秒。取消当前步只取消等待，不停止后台任务。子会话进入 WaitingForInput 时立即返回阻塞状态，父会话可以处理问题或让用户审批。

子会话的完成指当前一轮工作停下，它仍保留记录并可继续接收 `tell_child`。等待读取实时状态，同时考虑排队、正在推进及待恢复答复，避免把两步之间的 Idle 当作完成。纯嵌入宿主需提供实时状态通道；缺少通道时返回明确说明。

## 自动回报

后台进程自己退出或达到执行时限后，核心保存最终状态、退出码/原因及已收集输出，向所属会话追加一对完整的工具调用与结果。子 agent 的回报和进程通知共用 `CommandDispatcher.InjectReport`，并统一由 `Injected` 标识供配对恢复逻辑识别。

空闲会话自动推进，正在运行的会话排队合并。正在等待用户回答的会话保留问题，回报排队等答复恢复后消费。已归档或已删除的会话不被唤醒。手动停止已有直接回执，核心退出及重启恢复也不另发自动唤醒。

进程通知包含任务种类、结束状态、退出码/原因以及最多 4 KiB 的日志片段；全量已保存输出通过 `job_output` 分页读取。通知是核心注入，未新增 TimelineEvent 判别式，也不冒充用户发言。

## 用户操作

CLI：

```text
jobs [会话id]
job output <任务id> [--offset <字节位置>]
job kill <任务id>
```

后两条使用控制台当前会话。未知 job 子命令或非法参数返回用法错误，不会发送给模型。

WebSocket 命令：`jobs.list`、`job.output`、`job.kill`，均携带 `sessionId`；输出与停止命令另带 `jobId`。输出可带 `offset`。

HTTP 查询：

- `GET /sessions/{id}/jobs`
- `GET /sessions/{id}/jobs/{jobId}/output?offset=0`

头部会话中的后台任务面板可刷新任务、分页看输出及停止。用户操作不受模型权限轴限制，因此模型切到 off 后，用户仍可停进程。任务归属校验由同一个宿主负责。

## 生命周期与边界

不设会话后台任务数量配额；同一会话的模型步仍串行。每个进程最多保留 4 MiB 输出，一次读取最多 64 KiB，超限后仍排空管道。正常核心退出停止后台任务并记录原因；强杀/断电无法保证执行清理，下次启动将残留 Running 标记为 Lost，避免按已复用 pid 误杀其他进程。

后台 dotnet 沿用参数白名单与环境清理，当前不参与前台 dotnet 的同目录互斥，应避免同时在相同目录启动多个构建。会话删除暂不连带停止其进程任务，最终由显式停止或核心退出收尾。浏览器交互有静态接线与脚本语法检查，尚未完成真实浏览器端到端验收。
